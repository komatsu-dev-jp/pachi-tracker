# PachiTracker iOS リデザイン brief

## 目的

`pachi-ios-redesign.html` は、PachiTracker の記録画面を iOS のグループ化リスト風に整理した**実装前の視覚レビュー用モック**です。
店内で片手操作する利用状況を前提に、画面を開いた直後に「続けるか、様子を見るか、やめるか」を理解できる情報の並びを確認します。

このファイルはデザインの確認用であり、アプリ本体の画面や判定計算を直接変更するものではありません。

## 今回確認すること

1. 画面上部に結論（現在の判断）を置くと、3秒以内に状況を読めるか
2. 判断の根拠を、実測回転率・ボーダー差・期待値・投資額の4項目に絞っても足りるか
3. 44px以上のタップ領域で、片手操作の負担が増えないか
4. 393px幅（iPhone相当）と320px幅でも、文字や金額が横にはみ出さないか
5. ダークテーマとライトテーマを切り替えても、情報の優先順位が保たれるか

## 画面の構成

上から順に、次の情報階層にしています。

| 順番 | 表示 | 役割 |
| --- | --- | --- |
| 1 | 店舗・台情報 | 今どの台を記録しているかを確認する |
| 2 | 記録 / 判断 / 履歴 | 実戦中に必要な情報へ切り替える |
| 3 | 現在の判断 | 結論と信頼度を最初に読む |
| 4 | 判断に使う数字 | 結論の根拠を4つまで確認する |
| 5 | 判断の理由 | 数字の意味を短い文章で補足する |
| 6 | 回転数を入力 | 次の記録操作へ進む |
| 7 | メインナビ | ホーム・記録・分析・設定を切り替える |

### 判断カード

- 「続行」を緑色の主要状態として表示する
- 信頼度は円形インジケーターで表示する
- ボーダー差や次の判断地点を文章でも補足する
- 数値はデザイン確認用のサンプルであり、実際の判定結果ではない

「様子見」「ヤメ」を追加するときも、色だけに頼らず、状態名と説明文を必ず併記します。色覚差があっても状態を読めるようにするためです。

## 既存設計との対応

- iOS風の色・カード・区切り線: [`docs/analysis-ios-design.md`](../analysis-ios-design.md)
- 記録中の判断ファースト方針: [`docs/decision-ui-design.md`](../decision-ui-design.md)
- 実際の判断表示部品: [`src/components/decision/DecisionTab.jsx`](../../src/components/decision/DecisionTab.jsx)
- 判断バッジの既存実装: [`src/components/decision/VerdictBadge.jsx`](../../src/components/decision/VerdictBadge.jsx)
- 既存のカラートークン: [`src/index.css`](../../src/index.css)

モックは既存の設計方針を視覚化するためのものです。実装時に次の保護対象を変更しないでください。

- `src/logic.js`
- `src/components/decision/evDecision.js`
- 期待値・金額・判定の計算式
- `rotRows`
- `src/__tests__/baseline.json`

これらを変更する必要が出た場合は、通常のUI調整ではなく、高危険度の変更として境界値テストと独立レビューを先に行います。

## 操作と状態の仮置き

HTMLモック内では、レビューしやすいように次の操作だけ実装しています。

- 右上のボタン: ダーク / ライトテーマを切り替える
- 「記録」「判断」「履歴」: 選択状態と補足テキストを切り替える
- 下部ナビ: 選択状態を切り替える
- 「回転数を入力」: 入力シートへ進む想定のメッセージを出す

上記は画面遷移の完成版ではありません。実装時は現在の `App.jsx` と既存のセッション状態を調べ、操作手順を増やさない形で接続します。

## 実装へ渡す受け入れ条件

- [ ] 画面の結論が、スクロールせずに読める
- [ ] 主要な操作ボタンのタップ領域が44px以上ある
- [ ] 393x852と幅320pxで横スクロールが発生しない
- [ ] ダーク・ライト両テーマで文字と状態色のコントラストを確認する
- [ ] 実装後のブラウザ確認でコンソールエラーが0件である
- [ ] 既存の「回転数を入力」から保存までのタップ数を理由なく増やさない
- [ ] 既存の計算式・保存形式・判断ロジックを変更しない
- [ ] 入力途中、データ不足、判定不能の状態にも説明文を用意する

## レビュー時の問い

1. 「続行」という結論の大きさは、店内で一目で読めるか
2. 「信頼度」の意味が、当たる確率と誤解されないか
3. 4つの指標のうち、実戦中に不要なものはないか
4. 判断の理由をタップして説明を読める導線が必要か
5. 「終了して保存」などの終了操作を同じ画面に置くべきか

## 見方

ブラウザ（Webページを見るアプリ）で `docs/design-review/pachi-ios-redesign.html` を開いてください。右上のテーマボタンと、画面中央のタブ・下部ナビを操作できます。

実装後の画面確認では、モックの見た目だけでなく、実データが少ない場合・長い機種名・大きな金額・ライトテーマでも同じ基準を確認します。
