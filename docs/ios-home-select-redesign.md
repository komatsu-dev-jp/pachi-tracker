### 1-4. 画面構成

**ホーム**: 7ブロックが等しい重さで縦積み。
`MonthlySummaryCard`（実収支+期待値+差分バナー+進捗バー+逆算パネル+複合チャート+月末見込み+プランリボン+詳細リンク の9要素入り巨大カード） → `NextActionCard` → リマインダー → 明日のリサーチ → 差玉解析 → 直近の記録 → 判断履歴 → 店舗データ状況。

**台選び**: `Header`（戻る＋タイトル） → プラン引継バナー → 鮮度バナー → 遊タイムボタン → KPI4列 → フィルタタブ → ホールマップ → 選択台の見込み → 学習サマリー → ポートフォリオ の10ブロック。

## 2. 刷新の設計原則

**大前提：機能は一つも削らず、装飾だけを引き算する。**

> 「ネオン間はなくて大丈夫です。機能は過不足なく実装しながら、シンプルにお願いします」（ユーザー判断、2026-07-26）

当初は「分析OS風ダークUI」の意匠（グロー・グラデーション・ガラス質感）を継承する方針だったが、**撤回した。**
装飾を全廃し、フラットな面・1pxの罫線・意味のある色だけで構成する。

### 2-1. やめる装飾

| 要素 | 現行の実装 | 変更後 |
|---|---|---|
| アイコン枠 | `NeonIconBox` — グラデーション背景 ＋ 外側グロー ＋ 内側ハイライト | 単色を15%で敷いた**平面の角丸四角**。グロー・グラデーションなし |
| カード | `glassCardStyle` — 半透明グラデ ＋ `backdrop-filter: blur(8px)` | **不透明な単色面** ＋ 1px罫線。ブラーなし |
| 地の色 | 濃紺グラデーション ＋ 上部の放射グロー | **単色**（`#06090f`） |
| CTA・バッジ | グラデーション ＋ カラーシャドウ | **単色塗り** |
| 数値 | `text-shadow` によるグロー | **なし** |
| 選択セル | 発光 ＋ 拡大 | **2pxのリング**のみ |
| 状態ピル | 明滅アニメーション | **なし**（アニメーションはシートの開閉だけ） |
| 装飾スパークライン | 実収支・期待値の飾り波形（ダミーデータ） | **削除**。残すのは実データ由来のグラフのみ |

### 2-1b. 色の使い方

**配色トークンの値は1つも変えない。** 変えるのは使い方だけ。

- 色は**意味を持つときだけ**使う — 緑＝プラス / 赤＝マイナス / 青＝操作 / 黄＝注意 / 紫＝対面
- それ以外は面（`--bg` / `--surface` / `--surface-hi`）・罫線（`--border`）・文字色（`--text` / `--sub` / `--sub-hi`）で構成する
- 装飾目的の着色は行わない

### 2-1c. 残すもの

| 要素 | 理由 |
|---|---|
| 円形信頼度リング（`VerdictBadge` 由来） | 確信度を数値＋弧で示す**情報表現**。グローだけ外して転用 |
| 過去推定回転率のスパークライン | 実データの推移 |
| バックテスト週次推移（MAE / 偏り / カバレッジ） | 実データの推移 |
| 月間推移グラフ（5系列） | 実データ。※扱いは 7-2 参照 |
| ヒートマップの色分け | ボーダー差の判定＝意味を持つ色 |

### 2-2. 入れ替える原則

1. **タイポスケールを iOS 準拠に敷き直す** — 最小 11pt、本文 15〜17pt、主要数値 28〜40pt。`-apple-system` を先頭に置いたフォントスタック＋ `font-variant-numeric: tabular-nums`。
2. **飾りではなく情報に紙面を使う** — 装飾・重複導線・ダミーグラフを削り、その分を数値と説明文の可読性に回す。
3. **ネイティブ構造を借りる** — Large Title、Inset Grouped List、detent シート、セグメンテッドコントロール。表面処理も iOS 標準に寄せた平面構成にする。
4. **横スクロールは対面ヒートマップの地図領域のみ許容** — それ以外では使わない（4-1b、ユーザー承認済み）。
5. **タップ領域は一律 44pt 以上**、主要 CTA は 52pt。
6. **配色トークンは1つも変えない** — `--bg #05070d` / `--surface #0e1117` / `--blue #38bdf8` / `--green #22c55e` はそのまま。変えるのは使い方だけ（2-1b）。

### 3-1. ヘッダーに状態を出す（ヒーロー案は撤回）

当初は `NextActionCard` を画面最上部のヒーローに昇格させる案だったが、**ユーザー指摘により撤回した。**

> 「ホーム画面の1番上のさ玉を解析するボタンは1番上だと違和感を覚えます。下にスクロールしていくと解析ボタンもあるのでそれでいい」

指摘は妥当で、最上部にヒーローCTAを置くと下の `DeltaStatusCard` の「差玉を解析」と**同じ操作のボタンが1画面に2つ並ぶ**。重複した導線は「3秒で理解できるか」を損なう。

したがって：

- `NextActionCard` は**現行の位置（`MonthlySummaryCard` の直後）のまま**。カードの中身も不変
- 最上部のヒーローは**作らない**
- 代わりに Large Title のサブ行へ `7月26日（日）・マルハン空港通店 ・ 実戦前` と出す。状態（稼働前 / 稼働中 / 稼働後）はここで判別でき、**ボタンは増えない**
- 状態文字列は `S.sessionStarted` と `archives` の当日判定から導出（既存の `hasTodayRecord` を流用、新規 state なし）

### 3-1a. ヘッダーの圧縮（あいさつを小さく）

> 「おはようございますは小さく」

現状のあいさつは `clamp(21px, 5.4vw, 26px)` の見出し（`HomeDashboard.css:41`）。ブランド行・サブコピーと合わせると、実測値が現れるまでに**約190px**を消費している。

| 要素 | 現行 | 案 |
|---|---|---|
| あいさつ | 21〜26px 見出し | **14.5pt** の小さい行 |
| Large Title | なし | **日付**「7月26日（日）」26pt |
| サブ行 | 「期待値を一つずつ積み上げましょう」10px | 「マルハン空港通店 ・ 実戦前」13pt |

月間カードが**約90px上がる**。あいさつ文言自体は削除せず、サイズと階層を変えるだけ。

### 3-1c. 「実収支・期待値」をグラフなしで分かりやすくする

> 「実収支、期待値のグラフは排除しもう少し分かりやすく」

**問題**: 実収支 `+38,200` と累計期待値 `+44,600` が同じ大きさで横並びになり、下にスパークラインが2本。「で、良いのか悪いのか」を知るには頭の中で引き算する必要がある。差分は下の赤いバナーに「入力済み記録は欠損 6,400円」と出るが、この文言は意味が取りづらい。

**案**:

```
実収支
+38,200円          ← 42pt・主役
実際に増えた金額 ・ 9件中 8件を入力済み

┌─────────────────────────────┐
│ 累計期待値（理論）  −  期待値との差 │
│ +44,600円              6,400円  │
└─────────────────────────────┘

期待値より 6,400円 少ない結果です。
短期のブレの範囲。打ち方が悪かったという意味ではありません。

期待値目標 60,000円 ────────── 74%
```

- **スパークライン2本を撤去**（`data-spark` の装飾グラフ。元々ダミー波形で実データではない）
- 実収支を42ptの主役に。期待値は比較対象として一段下げる
- 差分を「期待値との差」として明示し、引き算を画面側で済ませる
- 最後に**結論を一文**で置く

**文言の変更提案（要承認）**: 現行の `入力済み記録は欠損 / 余剰`（`HomeDashboard.jsx:125`）を「期待値より N円 少ない／多い結果です」に変更したい。
**値の定義（`projection.actualExpectedGap`）は一切変えず、表示ラベルのみ**の変更。差し戻し可能。

**保留**: 月間カード下部の「今月の推移と月末見込み」（`ComposedChart`、実収支・期待値・月末見込み・目標ペース・80%帯の5系列）は**残している**。ご指示は実収支・期待値の小グラフと解釈したため。これも不要なら折りたたみに送るか撤去する。

### 3-1b. 「明日のリサーチ」候補の折りたたみ

候補行（`PlanCandidateRow`）は最大5枚並び、1枚あたり約150pxのためホームが縦に伸びる。

- **上位2件（本命候補・予備）を常時表示**
- 残りは `すべての候補を見る（残り3件）` で開閉（`<div hidden>` の切替のみ、state 1つ）
- 検索・リスク絞り込みによる入れ替えは従来どおり月間プランシート側

候補の総数・並び順・役割ボタンの挙動は不変。**表示件数の初期値を変えるだけ。**

### 3-2. 月間サマリーの縮約案は撤回

当初は複合チャート・月末見込み・逆算パネルをシートへ送って3値に縮める案だったが、**採らない。**
ユーザー判断により並び順・展開状態は現行のままとし、変更は 3-1c（スパークライン撤去と差分主役の再構成）に限定する。

### 3-3. Inset Grouped List の適用範囲

**ホームのカード（差玉解析 / 直近の記録 / 判断履歴 / 店舗データ状況）はカードのまま残す。**
リスト化して1画面に畳む案は、表示項目が見えなくなるため採らなかった。

Inset Grouped List を使うのは、台選びの「分析」「ツール」グループ（店のクセと変化検知 / 予定時間の優先配分 / 遊タイム計算 / ことばの意味）のみ。
1行 = 左に**平面のアイコン枠（30pt、単色15%）** ＋ タイトル（16pt）＋ サブ1行（11.5pt）＋ 右に値（15pt）＋ chevron、行高 56pt。
グループのコンテナは不透明な単色面 ＋ 1px罫線。**設定画面の `SectionLabelV2` / `SectionCard` / `ListRow` の3ヘルパーをそのまま流用でき、`NeonIconBox` のグロー・グラデーション指定を外すだけで済む。**

### 3-4. `PlanEditor` を detent シートへ

#### キャンセル＝破棄を仕様として固定する

レビューで「安定に変更 → キャンセル → 開き直すと安定のまま」と報告された。
調査の結果、**これはモック側の不具合で、アプリ本体は正しく動いている**。

- `PlanEditor` は編集値をすべて**ローカル state** で保持する（`HomeDashboard.jsx:383` 以降の `useState` 群）
- 呼び出し側は `{planEditorOpen && (<PlanEditor … />)}` の条件レンダリング（`HomeDashboard.jsx:1395`）
- 閉じると**アンマウントされて state が消える** → 再度開くと `current`（保存済み `monthPlan`）から初期化される
- 永続化は `onSave` → `saveMonthPlan` の経路だけ

つまり現行実装は「保存したときだけ確定」になっている。**iOS 化でこれを壊さないこと**が要件。

| 閉じ方 | 期待動作 |
|---|---|
| 「このプランを保存」 | 確定（`onSave`） |
| 「キャンセル」 | **破棄** |
| 下スワイプ | **破棄** |
| 背景タップ | **破棄** |
| ✕ ボタン | **破棄** |

detent シート化では、下スワイプと背景タップという**新しい閉じ方が増える**。
どちらも `onClose` を通してアンマウントさせる（state を親へ引き上げない）こと。

将来、編集内容が重くなって破棄が惜しくなった場合は「変更を破棄しますか？」の確認を挟む。
ただし**現時点では不要**（アンマウント方式で十分かつ単純）。



グラバー（上端の横棒）、角丸24pt、`medium`（55%）/ `large` の2段階、背景スクロール停止、下ドラッグで閉じる。実装は CSS の `translateY` ＋ `touchmove` で足りる（新規ライブラリ不要）。

### 4-1b. 対面ヒートマップは「上下2段＋中央通路」を維持する（横スクロール例外は承認済み）

当初案は横スクロールを廃して `repeat(auto-fill, minmax(50px,1fr))` の折り返しにすることだったが、**ユーザー判断により上下2段＋中央通路を採る。**

> 「上下2段+通路の方が実際の島の感じがしていいかなと思います。ただ、横スクロール禁止はClaude MDありますが一旦どんな感じになるのか実装してください。」

#### 折り返しでは表せないもの

折り返しグリッドにすると、対面の対応関係が「同じ順番の台」までしか表せない。実際のホールは物理的に向かい合っているので、その空間感覚が失われる。`machine.pevidence.opposite.oppositeNum` を持っているのに視覚化できない。

#### 採る構成

```

┌──┬──┬──┬──┬──┬──┬──┬──┬──┬──┬──┬──┐
│121│122│123│124│125│126│127│128│129│130│131│132│
└──┴──┴──┴──┴──┴──┴──┴──┴──┴──┴──┴──┘
▨▨▨ 中央通路  ↕ 同じ縦位置が対面 ▨▨▨
┌──┬──┬──┬──┬──┬──┬──┬──┬──┬──┐
```

現行 `OppositePairMap` の構造（`.strategy-pair-scroll` + `.strategy-pair-canvas` + `PairIslandRow` × 2 + `reverse`）を**そのまま維持**する。改修は次の2点だけなので範囲は小さい。

1. **対面セルの強調** — 台を選ぶと、同じ縦位置の相手セルを紫（`--purple #c084fc`）の2pxリングで示す（グローなし・フラット）。現行は `opposite` 印（小さな「対」バッジ）のみで、選択との連動がない
2. **寸法の拡大** — セル幅 50pt、台番号 10.5pt→11pt、回転率 15pt、島見出し 13.5pt。島見出しと中央通路は `position: sticky; left: 0` で横スクロール中も画面内に残す

#### CLAUDE.md との抵触 → 例外として承認済み（2026-07-26）

A島12台 × 50pt ＝ 600pt で iPhone 16 Pro の 390pt を超えるため、**横スクロールは避けられない**。CLAUDE.md「横スクロール前提UIは禁止」に正面から抵触する。

> 「横スクロールはOKです。」（ユーザー判断、2026-07-26）

**承認された。** したがって：

- 上下2段＋中央通路で確定。折り返し版とレイアウト切替UIはモックから撤去した
- 実装時に **CLAUDE.md へ例外条項を追記する**。文案：

  ```
  - 横スクロール前提UIは禁止
    - 例外: 台選び（戦略マップ）の対面ヒートマップの地図領域のみ許容する。
      対面台の物理的な位置関係を再現することが機能の本質であり、
      折り返し表示では対応関係を表現できないため。
      地図領域以外への横スクロールの拡大は認めない。
  ```

- 島見出しと中央通路は `position: sticky; left: 0` で、横スクロール中も画面内に残す

### 4-2. ボトムシート化が中核である理由

現状：セルをタップ → `SelectedOutcomeSection` は地図の下にあるのでスクロール → 内容確認 → 別の台を見るため上へスクロールして戻る。**2台を比較するのに上下スクロール4回。**

案：セルをタップ → シートが下から `medium` detent で上がる。**地図は背後に見えたまま**なので、シートの外の別セルをそのままタップすると中身が差し替わる。**スクロール0回で何台でも比較できる。**

#### 実装仕様（ここを外すと成立しない）

初版のモックはこの挙動が**動いていなかった**。全画面のスクリムが地図を覆い、別の台を押せなかった。同じ失敗を実装で繰り返さないため、要件として固定する。

| 項目 | 要件 |
|---|---|
| モーダル性 | **非モーダル**。背景を覆うスクリムを置かない（置く場合は `pointer-events: none`） |
| 高さ | 画面の **58% まで**。上部の地図が必ず見えている状態を保つ |
| 台の切替 | シートを開いたまま別セルをタップ → **開き直さず中身だけ差し替える**（`openSheet` を再実行しない） |
| 閉じ方 | **✕ ボタン**（右上、44pt）と**下スワイプ**の2通り。どちらも必須 |
| 対比 | プラン編集・通知・店舗切替・ヘルプは**モーダル**（スクリムあり）。台の詳細だけ非モーダル |

> **検証方法**: 台123 のシートを開いたまま台124 をタップし、シートが閉じずに台124 の内容へ変わることを確認する。

| 操作 | 現状 | 案 |
|---|---|---|
| 起動 → 今日やることを知る | 起動 + スクロール1〜2回 | 起動のみ（0スクロール） |
| 台選び → 1台の見込み確認 | タブ + セルタップ + スクロール | タブ + セルタップ |
| 台選び → 2台を比較 | セル + スクロール + セル + スクロール（計4） | セル + セル（計2） |
| 月間プラン編集 | ホーム + カード内ボタン | ホーム + リスト1行 |

**すべてタップ数は同数または減少**。CLAUDE.md「タップ数増加を伴う改修は禁止」を満たす。

## 9. 状態カタログ（実装時に作り分ける11状態）

正常系だけのモックは危険、という指摘を受けて追加。表示文言まで定義する。

| 状態 | 画面 | 表示 | 次の行動 |
|---|---|---|---|
| 店舗未登録 | 台選び / ホーム | 「店舗が登録されていません」 | 店舗を登録する |
| 機種未登録 | 月間プラン | 「登録済みの機種がありません」 | 設定を開く |
| 差玉データなし | 台選び | 「差玉データがありません」 | 差玉を解析する |
| 良台候補 0件 | 台選び（フィルタ） | 「条件を満たす台がありません」 | 全台を表示 |
| 解析データが古い | 鮮度バナー | 「過去参考：7/18の解析（8日前）」＋判定停止 | 差玉を解析する |
| 解析日が未来/不正 | 鮮度バナー | 「解析日を確認してください」 | 解析日を修正する |
| 稼働中 | 台選び / 台詳細 | 「台123 で記録中」＋CTAが変化 | 記録中の台へ戻る |
| 稼働終了後 | ホーム | 「今日の実収支 +12,400円」 | 記録を確認する |
| 読み込み中 | 共通 | スケルトンのみ（古い値を見せない） | — |
| 保存失敗 | 差玉解析 / プラン | 「保存できませんでした」＋**入力内容は保持** | もう一度保存 / 下書き保持 |
| オフライン | 共通 | 「オフラインです。記録・保存は使えます」 | — |
| プラン未作成/再確認 | ホーム | 「本命候補を選んでください」 | 条件外を解除 / 候補を選ぶ |

### 9-1. 設計方針

1. **空状態は必ず次の行動ボタンを持つ** — 行き止まりを作らない
2. **失敗状態は入力内容を破棄しない** — 再試行できる形で残す
3. **データが古い・不正なときは、数値を出すより判定を止める** — 現行 `FreshnessBanner` の設計を踏襲する
