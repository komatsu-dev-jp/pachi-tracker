## 1. 現状の計測結果（推測ではなく実測）

### 1-1. 文字サイズ

| ファイル | 10px以下の font-size 宣言 | 14px以上 |
|---|---|---|
| `HomeDashboard.css` | **88件**（7px×8 / 8px×21 / 9px×29 / 10px×30） | 12件 |
| `StrategyMapDashboard.css` | **43件**（6px×2 / 7px×10 / 8px×20 / 9px×11） | 10件 |
| `StrategyMapDashboard.jsx`（インライン） | **35件**（7px×1 / 8px×15 / 9px×19） | 11件 |

Apple HIG の最小推奨は 11pt、本文は 17pt。現状は本文相当の情報の大半が 8〜10px に置かれている。
CLAUDE.md の「視認性 > 美しさ」「忙しい人が3秒で理解できるか」という基準に対し、ここが最大のギャップ。

### 1-2. タップ領域 44px 未満の要素

- `.home-bell`（通知ベル）: 36×36px — `HomeDashboard.css:37`
- 戦略マップのヘルプボタン「?」: 38×38px — `StrategyMapDashboard.jsx:250`
- `.home-target-edit`（月間プラン編集）: minHeight 34px — `HomeDashboard.css:59`

### 1-3. 横スクロール

CLAUDE.md「横スクロール前提UIは禁止」に対し、`StrategyMapDashboard.css` に `overflow-x: auto` が **5箇所**（L11 島一覧 / L32 台ストリップ / L75 / L175 / L264）。
特に `.strategy-pair-scroll`（対面島マップ）は `minWidth: columns * 58 - 4` で幅を確保しており、台数が多い島では横スクロールが必須になる。

### 1-4. 画面構成

**ホーム**: 7ブロックが等しい重さで縦積み。
`MonthlySummaryCard`（実収支+期待値+差分バナー+進捗バー+逆算パネル+複合チャート+月末見込み+プランリボン+詳細リンク の9要素入り巨大カード） → `NextActionCard` → リマインダー → 明日のリサーチ → 差玉解析 → 直近の記録 → 判断履歴 → 店舗データ状況。

問題は順序。**「今日なにをするか」を示す `NextActionCard` が、スクロールしないと見えない位置にある**。起動直後に見えるのは月間チャート。

**台選び**: `Header`（戻る＋タイトル） → プラン引継バナー → 鮮度バナー → 遊タイムボタン → KPI4列 → フィルタタブ → ホールマップ → 選択台の見込み → 学習サマリー → ポートフォリオ の10ブロック。

問題は2つ。
1. **ルートタブなのに戻るボタンがある**（`StrategyMapDashboard.jsx:212`）。タブバーから直接来る画面に戻るボタンを置くのは iOS のアンチパターン。押した先（ホーム）はタブバーにも存在する。
2. **台を選んだ結果（`SelectedOutcomeSection`）が地図のはるか下**。セルをタップ → 下へスクロールして確認 → 別の台を見るため上へ戻る、を繰り返す。片手・立位での比較操作としては最悪の導線。

### 1-5. iOS標準構造の不使用

Large Title、Inset Grouped List、detent付きシート、セグメンテッドコントロール、グラバー付きモーダル — いずれも未使用。すべて独自カードで自作しているため、iPhone ユーザーの手癖（上端スワイプ、シートを下に引いて閉じる、リスト行の右chevron）が効かない。
`PlanEditor`（`HomeDashboard.jsx:568`）は独自の全画面オーバーレイで、グラバーなし・ドラッグで閉じられない。

## 2. 刷新の設計原則

**大前提：既存の意匠は継承する。** 本案が入れ替えるのは「構造」と「タイポグラフィ」だけで、視覚的な世界観は変えない。
52回のマージで積み上げてきた「分析OS風ダークUI」を、iOS の構造に翻訳する作業と位置づける。

### 2-1. 継承する意匠（変更しない）

| 要素 | 現行の実装 | 扱い |
|---|---|---|
| 地の色 | `linear-gradient(180deg, #030714, #06101e)` の濃紺グラデーション | そのまま |
| カード | `glassCardStyle` — 半透明濃紺グラデ ＋ `backdrop-filter: blur(8px)` | そのまま。iOS のリストにも適用する |
| カード枠線 | `color-mix(in srgb, #5b8fcf 16%, transparent)` の薄い青グレー | そのまま |
| アイコン枠 | `NeonIconBox` — グラデーション背景 ＋ 外側グロー ＋ 内側ハイライト | **そのままリスト行に流用する** |
| アクセント | `#38bdf8` / `#0A84FF` / `#21D99B` / `#FFB020` / `#FF5A5F` / `#C084FC` | そのまま |
| スパークライン | LCG によるシード固定ランダムウォーク ＋ グラデーション fill | そのまま。指標カードとシートに残す |
| 円形リング | `VerdictBadge` の円形信頼度リング | **台選びの判定ヒーローに転用する** |
| 文字色 | メイン `var(--text)` / サブ `#6f8aae` / 強調 `#7da4cf` | そのまま |

### 2-2. 入れ替える原則

1. **タイポスケールを iOS 準拠に敷き直す** — 最小 11pt、本文 15〜17pt、主要数値 28〜40pt。`-apple-system` を先頭に置いたフォントスタック＋ `font-variant-numeric: tabular-nums`。
2. **1画面1決定** — その画面を開いた瞬間、スクロールなしで次の行動が決まる。
3. **ネイティブ構造を借りる** — Large Title、Inset Grouped List、detent シート、セグメンテッドコントロール。ただし**表面処理は既存のガラスカードのまま**。ネイティブの構造 × 既存の意匠、という組み合わせにする。
4. **横スクロール全廃** — 縦フィットのグリッドに置き換える。
5. **タップ領域は一律 44pt 以上**、主要 CTA は 52pt。
6. **配色トークンは1つも変えない** — `--bg #05070d` / `--surface #0e1117` / `--blue #38bdf8` / `--green #22c55e` はそのまま。

## 3. ホーム画面 新構成

```
┌─────────────────────────────┐
│ ホーム                    🔔 │ ← Large Title（スクロールで44ptバーへ収束）
│ 7/26(日)・マルハン空港通店     │
├─────────────────────────────┤
│ ■ 今日のカード（Hero）        │ ← ここだけで次の行動が決まる
│   状態バッジ                  │
│   大見出し（34pt）            │
│   補足1行                    │
│   [ 大CTA 50pt ]             │
├─────────────────────────────┤
│ 今月  実収支 / 期待値 / 進捗   │ ← 3値のみ。チャートは行タップでシート
├─────────────────────────────┤
│ ▤ 差玉解析          3台 ›    │ ← Inset Grouped List
│ ▤ 直近の記録    +12,400円 ›  │
│ ▤ 判断履歴          8件 ›    │
│ ▤ 店舗データ       67% ›     │
├─────────────────────────────┤
│ ▤ 今月の稼働プラン        ›  │ ← タップで detent シート
└─────────────────────────────┘
```

### 3-1. 「今日のカード」（新規・最重要）

現状の `NextActionCard` をヒーローに昇格し、画面最上部に置く。稼働状態で3表示に分岐する。

| 状態 | 見出し | CTA |
|---|---|---|
| 稼働前 | 「今日の狙いを決める」/ プラン未設定なら「今月のプランを作る」 | 台選びを開く / プランを作る |
| 稼働中 | 判定ラベル（続行 / 様子見 / ヤメ）＋ 現在持ち玉 | 記録に戻る |
| 稼働後 | 今日の実収支 | 記録を確認 |

データソースは現状の `nextAction`（`HomeDashboard.jsx:1143`）と `S.sessionStarted` / `S.ev` をそのまま使う。**新しい state は追加しない。**

### 3-2. 月間サマリーの縮約

現状の `MonthlySummaryCard` は9要素入りで縦に長い。これを **実収支 / 累計期待値 / 目標進捗バー の3値だけ**に縮める。

- 複合チャート（`ComposedChart`）・月末見込み・`GoalBackcastPanel` は**削除せず**、カード末尾の「今月の推移を見る ›」からシートで開く。
- 「月間プラン」リボンはリストの1行へ移動。

> CLAUDE.md「既存UI・入力項目・表示項目を勝手に削除しない」に従い、**どの要素も削除せず、露出階層を変えるだけ**。

### 3-3. Inset Grouped List

差玉解析 / 直近の記録 / 判断履歴 / 店舗データ状況 を、iOS 設定アプリと同じ角丸グループのリストにする。
1行 = 左に **`NeonIconBox`（34pt、既存の設定画面と同一意匠）** ＋ タイトル（16pt）＋ サブ1行（12pt）＋ 右に値（15.5pt）＋ chevron、行高 58pt。
グループのコンテナは `glassCardStyle` をそのまま使う。**設定画面ですでに実績のある `SectionLabelV2` / `SectionCard` / `ListRow` の3ヘルパーを流用でき、新規実装はほぼ不要。**

現状はそれぞれが独立カード（`DeltaStatusCard` / `RecentCard` / `JudgmentCard` / `StoreDataCard`）で、合計すると画面3枚分。リスト化で1画面に収まり、各詳細は行タップでシートに入る。

### 3-4. `PlanEditor` を detent シートへ

グラバー（上端の横棒）、角丸24pt、`medium`（55%）/ `large` の2段階、背景スクロール停止、下ドラッグで閉じる。実装は CSS の `translateY` ＋ `touchmove` で足りる（新規ライブラリ不要）。

## 4. 台選びページ 新構成

```

│ 解析 7/25・候補 12台          │
├─────────────────────────────┤
│ 本命                          │ ← 決定ヒーローを最上部に

│ +2,840 円/h（34pt）           │
│ 予測回転率 19.8/k・確信度 72% │
├─────────────────────────────┤
│ [ 全台 │ 候補 │ 本命 ]        │ ← セグメンテッドコントロール 44pt
├─────────────────────────────┤
│ A島（入口側）        12台 ⌄   │ ← 島＝折りたたみセクション
│  ┌──┬──┬──┬──┬──┬──┐        │ ← 横スクロール廃止・auto-fill で折り返し

    セルをタップ ↓

┌─────────────────────────────┐
│ （地図は背後に残る）           │
│ ▬▬▬                          │ ← グラバー
│ 台123  Pエヴァンゲリオン       │
│ 着席推奨 ●                    │
│ 時給 +2,840円 / 予定収支 +8,500│

└─────────────────────────────┘  detent: medium
```

### 4-1. 変更点

| # | 変更 | 理由 |
|---|---|---|
| 1 | **戻るボタン廃止** | ルートタブ。戻り先はタブバーに存在する |
| 2 | **決定ヒーローを最上部へ** | 現状は KPI 4列が先に来て「で、どの台？」が下 |
| 3 | **KPI 4列 → ヒーローに統合** | 390px幅で1枚85px・数値16px/単位8pxは判読限界。本命の期待値を40ptで出し、右に**既存の円形信頼度リング**（`VerdictBadge` と同じ意匠）で確信度、下段に予測回転率／ボーダー差／予定収支を並べる |
| 4 | **フィルタをセグメンテッドコントロールへ** | 現状56pt高のカスタムピル。ネイティブ形状で意味が即伝わる |
| 5 | **地図の横スクロール廃止** | `grid-template-columns: repeat(auto-fill, minmax(52px, 1fr))` で折り返す。島は縦に積み、折りたたみで長さを制御 |
| 6 | **選択台の見込みをボトムシート化** | 本案の中核。次項 |
| 7 | **学習/ポートフォリオ/遊タイムをリスト行へ** | 常時展開する情報ではない |

### 4-2. ボトムシート化が中核である理由

現状：セルをタップ → `SelectedOutcomeSection` は地図の下にあるのでスクロール → 内容確認 → 別の台を見るため上へスクロールして戻る。**2台を比較するのに上下スクロール4回。**

案：セルをタップ → シートが下から `medium` detent で上がる。**地図は背後に見えたまま**なので、シートの外の別セルをそのままタップすると中身が差し替わる。**スクロール0回で何台でも比較できる。**

| 操作 | 現状 | 案 |
|---|---|---|
| 起動 → 今日やることを知る | 起動 + スクロール1〜2回 | 起動のみ（0スクロール） |
| 台選び → 1台の見込み確認 | タブ + セルタップ + スクロール | タブ + セルタップ |
| 台選び → 2台を比較 | セル + スクロール + セル + スクロール（計4） | セル + セル（計2） |
| 月間プラン編集 | ホーム + カード内ボタン | ホーム + リスト1行 |

**すべてタップ数は同数または減少**。CLAUDE.md「タップ数増加を伴う改修は禁止」を満たす。

## 7. 未確定・要判断

1. **Phase 4 の対面島表示** — 現状の `OppositePairMap` は「同じ縦位置＝対面」を横スクロールで表現している。縦フィットに変えると対面の対応関係が視覚的に表せなくなる。代替案は (a) 島を上下2段に並べて中央に通路線、(b) 対面台を各セルの副表示に出す、の2つ。どちらを採るかは要判断。
2. **月間チャートの既定表示** — 縮約案ではチャートを1タップ奥に送る。毎日チャートを見たい運用なら、既定展開に戻す選択もある。
3. **ヒーローの稼働中表示** — 判定ラベルを出す場合、`evDecision` の verdict を参照するだけで閾値には触れないが、ホームと記録画面で同じ判定が2箇所に出ることになる。重複を許容するか要判断。
